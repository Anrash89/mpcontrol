# Селлер · CRM для Ozon и Wildberries

Адаптивный сайт для команды. Доступы выдаёт администратор. У сотрудников свои очереди, а руководитель видит входящие заявки, проверки, просрочки, конфликты сроков и риски запусков.

## Быстро посмотреть на GitHub Pages

1. Загрузите содержимое архива в корень репозитория.
2. В **Settings → Pages** выберите **Deploy from a branch → main → /docs**.
3. Откройте ссылку GitHub Pages. Статический сайт откроется с демонстрационными данными. Кнопка **Сменить роль** позволяет пройти процесс за руководителя, автора заявки и исполнителя. Изменения в демоверсии сбрасываются при перезагрузке.

## Запустить рабочий сайт

Для общей базы и аккаунтов запустите приложение на компьютере или сервере с **Node.js 24+**. Оно отдаёт интерфейс, хранит задачи, комментарии и файлы в SQLite и выполняет расписание. Установка npm-зависимостей не требуется.

В папке проекта создайте сотрудников. Пароли передаются через стандартный ввод. В Bash можно набрать следующие команды, а после каждой команды с `read` ввести выбранный пароль и нажать Enter.

```bash
read -rsp 'Пароль руководителя: ' sellerdesk_password; printf '\n'
printf '%s\n' "$sellerdesk_password" | node server.mjs add-user ilya lead "Илья"
unset sellerdesk_password

read -rsp 'Пароль сотрудника: ' sellerdesk_password; printf '\n'
printf '%s\n' "$sellerdesk_password" | node server.mjs add-user design member "Мария" "Дизайнер"
unset sellerdesk_password

npm start
```

Логин — от 3 символов латиницей, пароль — от 12 символов. Повтор команды с тем же логином меняет пароль, имя и роль и завершает прежние сессии. Для локальной проверки откройте **http://127.0.0.1:8080/**.

### Доступ с телефона и компьютера

На VDS запустите приложение постоянно и поставьте перед ним HTTPS-прокси на своём домене. Сайт и его серверная часть работают по одному адресу. Пример настроек запуска в Bash:

```bash
APP_ORIGIN=https://tasks.example.ru APP_TIMEZONE=Asia/Novosibirsk npm start
```

Пример блока Nginx для домена, на котором уже настроены сертификат и HTTPS:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    client_max_body_size 8m;
}
```

Откройте этот HTTPS-адрес на телефоне и компьютере. Данные общие для участников рабочего пространства и обновляются при возвращении на вкладку и примерно раз в 12 секунд. Для постоянной работы используйте менеджер процессов на сервере. Для резервного копирования остановите приложение и скопируйте каталог `data/` целиком. Можно указать отдельный постоянный каталог через `DATA_DIR`. Рабочую базу, пароли и копии файлов в GitHub загружать не нужно.

## Как пользоваться

- **Заявки и задачи.** Сотрудник создаёт заявку с целью, площадкой, товаром и материалами. Руководитель уточняет её либо назначает исполнителя, срок и приоритет, видя его загрузку. Исполнитель отправляет результат на проверку. Автор принимает работу или возвращает ту же задачу с комментарием. После приёмки новое изменение оформляется отдельной заявкой по тому же товару.
- **Товары и запуски.** У товара свои артикулы и ссылки на обе площадки, а также история задач. В запуске видны план поставки, дата старта, координатор, этапы и три отдельных согласования. Даты и зависимости обновляются вручную. Система подсвечивает риски по просроченным этапам, задержке приёмки и незакрытым согласованиям.
- **Поставки и продвижение.** Можно указать плановые и фактические даты отгрузки, приёмки, отправки образца и публикации, добавить ссылку и привязать запись к запуску.
- **Регулярные задачи.** Есть шаблоны чек-листа менеджера и отчёта по продажам и расходам. Активный сервер создаёт задачи ежедневно, по будням или в выбранный день недели. Расписание использует `APP_TIMEZONE`, по умолчанию Новосибирск. В демоверсии расписание срабатывает при сохранении шаблона за подходящую текущую дату.
- **Файлы.** До 8 МБ на файл и 20 файлов на задачу. Файлы загружаются в карточке заявки после создания. Пользователи рабочего пространства могут видеть задачи и скачивать их материалы. Изменения и переходы ограничены ролями.
- **Импорт.** Если есть JSON-копия из первой версии, руководитель может импортировать её в настройках. Задачи переходят в его очередь с исходными статусами, площадками и сроками.

Конфликт сроков отмечается, когда у исполнителя две или больше активных задач с одним дедлайном. Учёт трудозатрат, автоматический пересчёт дат зависимых этапов и интеграции с кабинетами площадок в этой версии отсутствуют.
